End-to-End Hosting Architecture

How our modular tools interact with your production Caddy instance on the VPS.

1

Production Server

Your VPS runs Caddy with /etc/caddy/caddy.json managing active SSL certificates and reverse proxies.

systemctl status caddy
2

Inspect with caddy-cli

Run caddy-cli -p to instantly detect occupied ports and open port slots before launching new applications.

npx caddy-cli -p
3

Generate with caddy-template

Produce a guaranteed, valid Caddy JSON route block tailored for WebSocket proxying or static serving.

npx caddy-template proxy <host> <port>
4

Zero-Downtime Reload

Append the JSON route into caddy.json and reload without dropping a single active WebSocket connection.

caddy reload --config caddy.json

Why We Standardize on Native Caddy JSON

Caddyfile is an adapter; native JSON is Caddy's true foundational engine.

Zero-Downtime Reconfiguration

Native JSON enables Caddy to update routing tables in-memory via the Admin API without terminating active WebSocket streams or dropping live user connections.

Programmatic Automation

Unlike plain text configuration files that require regex parsing, native JSON allows tools like caddy-cli and caddy-template to safely read and write configurations.

Unrestricted Module Access

Every feature, module, and plugin in Caddy is designed first in JSON. Standardizing on JSON unlocks 100% of Caddy's architectural capabilities.
